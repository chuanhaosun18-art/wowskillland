产品设计：迷茫期路由器（工程可开工版）

一个入口、三个流、一份地图、一个供给端。建议产品名「路口」（备选「走过」），一句话定位：每一次"我不知道"，都有人真走过。三条产品纪律贯穿全部界面：不测评、不建议、不承诺。

供给的三层结构：我们做的是"能行动的经验贴"

好的经验贴从不靠给答案解决迷茫——它让人在别人的故事里认出自己，顿悟发生在读者脑子里。因此供给分三层，缺一不可：故事层（学长口述全文，共鸣的载体，挂在卡背后可下钻）、卡片层（抽出的可执行第一步，补经验贴"读完不知道明天干嘛"的缺陷）、分布层（分叉数据与失败恢复卡，补单篇经验贴样本=1 和幸存者偏差的缺陷）。匹配的不是"最佳答案"，而是"处境和你最像的人的完整经历"——推荐理由直接写在界面上："TA 当年也是二本转码、也是大二下才开始慌的。"

六个界面（按用户旅程排列）

S1 · 入口对话（唯一入口）路由器
  • 只有一个输入框："说说你现在的不知道"。用户一句话进来，路由器判定迷茫形态：探索型 / 抉择型 / 行动型 / 情绪类（拦截，给校内心理支持入口，不落任何记录）。
  • 判定结果必须明示："听起来你还没想清楚要什么——我们先不聊选择，先找几件值得试的小事。" 路由透明本身是信任的一部分，也是兜底：判错了用户可以一键改道。
S2 · 探索流：访谈 → 假设 → 选卡探索型出口
  • 轻访谈 ≤5 轮、每轮 1–2 问，只采处境与行为信号（高中为什么熬过夜 / 每周自由时间 / 硬约束），不做任何人格测评。
  • 产出 3 张方向假设卡，每张必须引用访谈原话作为依据（"你说竞赛熬夜是高中最爽的时刻→技术深水区值得一试"），下挂 1–2 张匹配的第一步卡。
  • 第一步卡展示：两周剧本、完成标准、学长判断点、不适合谁、同处境验证数（9/11 说成立）、去向分布、choose_if 一句话。
  • 每张卡可下钻"TA 的完整故事"：学长口述全文——当年的处境原话、纠结、决定、后来。故事层负责共鸣，卡片层负责行动，推荐理由明示处境相似点。
S3 · 微尝试进行中（Skill 的运行时）任务态薄版
  • 选卡即装载：卡的剧本、判断点、边界、学长原材料被挂进用户专属陪跑 Agent（工程上=编译成 SKILL.md 挂给会话，与 Claude/扣子 Skill 机制同构）。AI 从通用聊天变成"带着这位学长经验的陪跑者"。
  • 执行中四种调用时刻：① 参数化展开——剧本 + 你的课表 → 本周具体安排（"你周三下午没课，建议周三写周四早上发，学长说早上发回复率高"）；② 执行中求助——用学长当年的原信生成你的版本，产出物里流着学长经验的血；③ 判断点定时触发——第 3 天你犹豫时，学长当年的想法主动递到你面前；④ 边界停机——处境越界（"我每周只剩 2 小时了"）时卡主动喊停"这张卡不适用了"。
  • 多卡可组合同载：方向探索卡 + 同专业时间模板卡，排周计划时两张卡约束同时生效——"组合不同人的经验"在此发生，用户无需任何编排操作。
  • 结束（或中途放弃）时只问两个问题：哪个时刻你忘了时间？哪个时刻你想逃？外加一句 verdict：这张卡在你的情况下成立吗（成立 / 不成立 + 一句反例）。放弃不是失败：原因同样落地图、给卡片积累边界数据。
  • 一句话区别：帖子只能被读，Skill 被执行——它把学长的剧本参数化到你的课表里，用学长的原材料帮你产出你的版本，在你最容易放弃的那天把学长的判断递到你面前，并且在自己不适用的时候主动喊停。
S4 · 探索地图（个人页）自我认知的载体
  • 时间轴叙事：什么时候带着什么迷茫来过、试了什么、感受原话是什么、下一步试什么。AI 生成叙事段落，原始记录可下钻。
  • 硬约束：禁止评价性词汇（优秀 / 擅长 / 适合），只允许描述行为与引用本人原话。无分数、无雷达图、无标签——这一页就是对评委"不量化人"的直接回答。
S5 · 路口页抉择型出口
  • 输入"该保研还是就业"类问题后展示：走过这个路口的总人数、各去向的绝对人数、改道最常发生的节点、每一支的代价原话（学长一句话）。
  • 页面顶部固定一行："我们不替你选，只让你看见走过的人。" 全页无建议、无倾向排序、无百分比。
S6 · 学长录入端供给闭环
  • 10 分钟访谈式录入：AI 问、学长说，自动抽取四槽（触发处境 / 两周剧本 / 判断点 / 不适合谁）+ 当时的感受，学长只确认不撰写。
  • 每个字段必须对应口述原文，对不上的丢弃（沿用"无来源即丢弃"）。"不适合谁"留空则不能发布。
  • 口述全文整理后保留为故事层内容（学长确认脱敏后发布）——它不只是溯源凭证，本身就是产品的第一等供给。
编排态的处理

行动型迷茫（"我决定考研了怎么排"）在决赛版本里不做完整交互：路由器识别后展示一份预生成的编排示例并口述机制。它是 PRD F17 的存量能力，答辩讲"产品长大后的样子"时再展开，不占开发时间。

Skill 运行时与被动供给（飞轮）

Skill 包格式（纯文本 + 提示词，48h 可实现）

  • instructions（提示词段）：学长经验转成的行为约束——判断点怎么提醒、什么信号说什么话。直接注入陪跑 Agent 上下文。
  • resources（文本资产段）：学长原信、模板、清单、当年的周安排——执行时的原材料。
  • triggers & boundary（触发与边界段）：时间触发（"第 3 天"）、语义触发（用户说"不想去了"）、停机条件（处境越界）。

运行时架构

  • 一个基础陪跑 Agent（通用能力 + "不测评不建议不承诺"纪律 system prompt），Skill 是动态挂载进它上下文的能力包。每轮循环：用户消息 → 规则检查在载 Skill 的触发条件 → 命中才注入对应段落 → Agent 融合生成回复。工程上是结构化 prompt 片段的条件注入，无黑科技，但演示效果是"AI 的行为肉眼可见地被学长经验改变"。
  • 两种运行形态：陪跑态（装载后持续生效两周，判断点定时触发、边界持续监控）与即时态（一次性调用"用学长模板写这封邮件"→ 单次产物）。同一个包，两种消费方式。

被动供给三级阶梯（用户只确认，不撰写）

层级触发方式用户动作产出
验证级每次尝试结束自动发生回答两问 + 一句 verdict卡片的验证数与边界数据——用了就是贡献了
变体级Agent 检测到实际走法偏离原卡剧本对 AI 生成的变体草稿点一次确认变体卡入池，署名归用户
新卡级用户走通许愿池里的无人区方向确认 AI 从轨迹蒸馏的新卡草稿 + 故事层他成为下一届的"学长"——产品主张的字面闭环
这同时回答了评委必问的供给续命问题

冷启动的 30–40 张卡用完之后，供给从哪来？——不靠邀请学长做慈善，靠使用本身的副产品：越多人用，验证越厚、变体越多、卡越准，飞轮成立。Demo 幕三结尾加一步：打卡完成后弹出 AI 蒸馏好的变体草稿，演示者一键确认发布——"消费者变供给者只花一次点击"，这个画面比任何飞轮图都有说服力。

AI 能力清单（6 个任务，每个带硬约束）

任务做什么硬约束（答辩即卖点）
A1 路由器一句话分类四态情绪类立即拦截；判定结果必须明示给用户
A2 迷茫访谈≤5 轮采集处境与行为信号只问经历不问"你觉得自己是什么样的人"；缺必采字段不往下走
A3 假设生成3 个方向假设每个假设必须附访谈原话依据；措辞是"值得一试"不是"你适合"
A4 卡片匹配规则过滤 + 生成 choose_if过滤是规则不是 AI（处境 vs trigger_context/boundary）；AI 只写"选它取决于什么"；无卡时如实说"还没人留下第一步"并落许愿池
A5 学长抽取口述 → 四槽 + 感受每个字段对应口述原文，对不上即丢弃；学长只确认不撰写
A6 地图叙事attempts → 叙事段落禁评价性形容词，只描述行为、引用原话

场景 × Skill 化判定（时期场景先拆解，再决定出口）

总原则：Skill 只承载"下一步动作"，不承载情绪修复和人生答案。每个场景拆成四种成分：可行动内核进卡（完成标准定义在自己的行动上）、认知校准给真实分布、不可控部分显式标注、纯情绪拦截或转介。

场景能进卡的部分（示例）给分布的部分不可控/情绪的处理
大一 · 方向迷茫方向微尝试第一步卡（已是主线）同处境学长的去向分布"兴趣何时出现"不可控；空心感不展开
大一 · 社交社交动作卡：组织宿舍聚餐的做法、社团面试自我介绍、破冰动作。完成标准="你发起了""多久才有稳定朋友圈"的真实分布（多数人第 8 周后）对方是否回应→标注不可控
大一 · 孤独感不做卡。孤独是状态不是任务——主动放弃 Skill 化是答辩加分项"同期有同感的比例"数据本身即有安慰力陪伴式回应；持续→校内心理入口
大一 · 时间掌控最强 Skill 区：同专业课表下的一周模板卡、ddl 急救卡。差异化=处境特异性，不是通用方法论学长真实每周有效学习时长分布（校准想象）—
大二 · peer pressure少量行动卡：调整信息环境、退出比较漩涡的具体做法主解药："37 位学长的大二暑假真实去向"——击穿"人均大厂"的失真参照系他人节奏不可控；焦虑持续→入口
大二 · 专业迷茫第一步卡：旁听目标专业课、约转过专业的学长（附邮件模板）转专业路口的分叉与代价原话转专业名额→标注不可控
大三 · 前途分水岭决定后的编排（F17）主交付：保研/考研/就业/出国路口页名额与 offer→标注不可控
大三 · 失败处理特色供给：失败恢复卡——"保研失利后 14 天补救时间线""挂科止损 SOP"。来自真正失败过的学长，知乎精华帖里没有，幸存者偏差最低"失败之后的人后来怎样了"——最有安慰力的分布冲击期先陪伴不推卡；结果不可控
矩阵的正确位置

"时期 × 场景"矩阵是内容生产的组织方式（指导学长访谈提纲的覆盖），不是产品导航。不要做"大一专区/大二专区"式的首页——用户入口仍然只有一个输入框，分场景发生在系统内部的路由里，不发生在界面上。

三个关键取舍

  • 两周时间盒无法现场发生 → Demo 用双视角预置数据：评委现场走"第 0 天"（入口到选卡），再切到一个预置的"第 14 天"学生账号看打卡记录和探索地图。时间流不需要现场证明，闭环逻辑需要。
  • 路由可能判错 → 不追求分类准确率，追求改道成本为零：判定结果明示 + 一键切换（"其实我已经决定了"）。答辩说法："我们不赌 AI 判得准，我们保证判错了用户一步就能纠正。"
  • 分叉样本量小 → 这恰是机制优势而非缺陷：只给绝对人数（"37 人走过"）不给百分比，小样本诚实呈现比大样本包装可信。样本量本身标注在页面上。
