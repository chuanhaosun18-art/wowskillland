# Skill 批量导入说明（给内容贡献者）

本说明面向**想往 SkillX 市场里加技能**的队友。
你整理的技能资料有两种交付方式，**推荐用方式二（GitHub PR）**，可以自助提交、全程留痕：

| 方式 | 适合场景 | 你要做的事 |
|---|---|---|
| **② GitHub PR（推荐）** | 会用 git / GitHub | 往仓库 `skills/` 目录加一个技能文件夹，提 PR，合入后自动具备导入条件 |
| ① 压缩包发回来 | 不想碰 git | 按下面格式整理目录，压缩成 zip 发回来，由运营侧导入 |

两种方式**内容格式完全一样**，下面都按同一套格式讲。

---

## 方式二：通过 GitHub PR 自助提交（推荐）

1. **fork 仓库**：https://github.com/chuanhaosun18-art/skillhub ，然后 clone 到本地。
2. 在仓库根目录 `skills/` 下新建一个文件夹，名字用你的技能名，例如 `skills/简历科研转产研/`。
3. 把 `skills/_template/skill.json.example` 复制一份进你的文件夹，改名为 `skill.json` 并填写内容（字段见下文）。
4. 选填：在文件夹里放 `skill.zip`（技能包）和 `proofs/`（证明截图）。
5. `git add` → `git commit` → push 到你的 fork → 向 `main` 分支提 **Pull Request**。
6. 合入 PR 后，维护者拉取代码、运行导入工具，你的技能就上架了，可以在市场搜到。

> 格式检查：仓库里已配置的自动校验会在 PR 时检查每个 `skill.json` 是否是合法 JSON、`name` 是否非空，不合规会直接标红提示，省去来回沟通。

---

## 方式一：压缩包发送

1. 把「技能资料」整个文件夹压缩成 zip（确保压缩包里能看到各技能子目录）。
2. 微信/网盘发回来即可，导入的人会用工具一键入库。
3. 入库结果会反馈给你：哪个技能上架了、哪个因为重名被跳过、哪个格式有问题需要改。

---

## 一、你要准备的目录结构

```
你的资料包/
├── 技能A-论文选题收敛/
│   ├── skill.json      ← 必填，技能的「身份证」
│   ├── skill.zip       ← 选填，技能包（提示词/模板/工具文件）
│   └── proofs/         ← 选填，证明这个技能有用的截图（多张）
├── 技能B-简历改写/
│   ├── skill.json
│   └── proofs/
└── 技能C-面试复盘/
    └── skill.json      ← 只有 json 也可以，只是质量分低一点
```

规则很简单：

1. **一个技能一个文件夹**，文件夹名随意（建议用技能名，方便对照）。
2. 每个技能文件夹里必须有一个 `skill.json`。
3. `skill.zip` 和 `proofs/` 都是可选的，但**填得越完整，技能的质量分越高，在市场的排序越靠前**。
4. 最后把整个资料包用 **zip 压缩**（Windows 右键 → 压缩为 zip 文件）发回来即可。

## 二、skill.json 怎么写

直接复制下面的模板，把占位内容替换成你自己的。

```json
{
  "name": "论文选题收敛术",
  "description": "把被导师退回来、范围太大的研究选题，一步步收窄成能落地执行的问题。",
  "category": "论文写作",
  "tags": ["选题", "开题报告", "研究生"],
  "version": "1.0.0",
  "task_intent": "thesis_topic",
  "goal": "2 小时内把过宽的选题收敛到可执行范围，并能说清为什么砍掉其它方向。",
  "done_criteria": [
    "选题一句话说清要解决什么问题",
    "列出被砍掉的方向及理由"
  ],
  "workflow": [
    "第一步：抄录导师原话和选题现状",
    "第二步：拆成子问题，按可行性打分",
    "第三步：砍掉低分方向，保留主问题"
  ],
  "boundary": {
    "not_applicable": ["纯情绪倾诉没有任务目标"],
    "handoff_trigger": ["需要实验数据但用户提供不了"],
    "fallback_path": "给一份自查清单让用户先自评"
  },
  "contract": {
    "input": "一段选题现状描述 + 导师反馈",
    "output": "收窄后的选题陈述 + 动作清单",
    "permissions": ["read_upload"]
  },
  "gotchas": [
    "导师退回两次以上先处理挫败情绪，再给方案"
  ]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 技能名，市场上展示的名字，**不能重复**（重复的会被跳过） |
| `description` | 建议 | 一句话说清解决什么问题，用户搜关键词靠它 |
| `category` | 建议 | 分类，如 论文写作 / 求职 / 面试 / 竞赛 |
| `tags` | 建议 | 3~4 个关键词数组，越多越好搜到 |
| `version` | 否 | 默认 `1.0.0` |
| `task_intent` | 否 | 任务类型，只认这几个值：`thesis_topic` 论文选题、`resume_rewrite` 简历改写、`resume_jd_align` 简历对齐JD、`report_structure` 汇报结构、`mock_interview` 模拟面试、`interview_review` 面试复盘、`project_convergence` 项目方案收敛、`literature_review` 文献综述、`content_script` 内容脚本。写别的会被忽略 |
| `goal` | 否 | 这个技能承诺达成的结果 |
| `done_criteria` | 否 | 完成标准，数组，至少 2 条更佳 |
| `workflow` | 否 | 执行步骤，数组，至少 3 步更佳 |
| `boundary` | 否 | 边界：`not_applicable` 不适合的场景、`handoff_trigger` 该停手交还给用户的情况、`fallback_path` 兜底方案 |
| `contract` | 否 | 输入输出约定 |
| `gotchas` | 否 | 踩过的坑/注意点，数组 |

> 注意：`skill.json` 必须是 **UTF-8 编码**，字段值不要用 `"` 之外的引号，写完可以放 [JSON 校验工具](https://www.json.cn) 里检查一下格式。

## 三、质量分怎么来的（重要）

导入时系统会根据字段完整度自动打分（0.3 ~ 0.8），**不会**因为缺字段而拒绝入库，只会影响排序。

| 加分项 | 说明 |
|---|---|
| description 非空 | +0.1 |
| tags 有 3 个以上 | +0.1 |
| goal 非空 | +0.05 |
| done_criteria 有 2 条以上 | +0.05 |
| workflow 有 3 步以上 | +0.1 |
| boundary 填了实质内容 | +0.05 |
| gotchas 有内容 | +0.05 |
| 带了 skill.zip | +0.05 |
| 带了 proofs/ 截图 | +0.05 |

所以**满分结构 = 写全字段 + 技能包 + 证明截图**。这本身就是内容质量的引导：技能写得越完整，用户看到越可信。

## 五、常见问题

**Q：我想覆盖已经上架的同名技能怎么办？**
导入侧加 `-force` 参数即可，旧版本会被删除后重新导入（含 zip、截图、评价一并清掉，慎用）。

**Q：技能包 skill.zip 里放什么？**
提示词文件、模板、检查清单、脚本等一切执行这个技能时要用到的东西。里面的文件名和目录结构会被完整登记，下载后原样还原。

**Q：证明图片 proofs/ 放什么？**
能证明「这个技能真的有用」的截图，比如：用它的产出结果、用户好评、任务完成记录。支持 jpg/png/gif/webp/bmp，单张不超过 10MB，命名随意（导入时自动编号）。
