# WowSkillLand 前端 × skillhub 后端 对接说明

后端仓库已克隆到 `../skillhub-backend`（Go + Gin + SQLite，已在本机编译通过并冒烟验证）。

## 一、怎么跑

```bash
# 后端（已编译好二进制 backend/backend）
cd skillhub-backend/backend
SKILLHUB_DATA="/Users/mac/Desktop/强生决赛/skillhub-data" \
DEEPSEEK_API_KEY="sk-..." \
./backend                      # 默认 http://localhost:8080

# 前端：直接打开 wowskillland-app/index.html
# 切真实模式：js/api.js 里 WowConfig.USE_MOCK = false
```

没配 `DEEPSEEK_API_KEY` 也能跑：意图路由降级为 `manual_fallback`（人工选任务），
工作台推进降级为手动记录，市场/认证/信任卡等接口不受影响。

登录：真实模式下前端首次调用会自动注册/登录演示账号 `wow_demo`，
也可调 `WowAPI.auth.login(account, password)`。Token 存 localStorage。

## 二、前端 6 个接口 → 后端真实端点（已在 js/api.js 写好映射）

| 前端方法 | 后端端点 | 说明 |
|---|---|---|
| `routeIntent` | `POST /api/growth/goals/interpret` | 后端六种 mode 映射为前端四态：`rejected+emotional_support→emotion`（全拦+心理资源）、`rejected→decide`（带分支人数）、`orchestration→action`、`task/clarify/manual_fallback→explore` |
| `runChat` | `POST /api/growth/executions` + `/:id/advance` | 陪跑对话 = 任务工作台。每步落 `execution_steps`，`decision` 停顿映射为判断点，`handoff` 映射为边界命中 |
| `extractSlots` | `POST /api/growth/backfill` | 学长口述 = 轨迹补录通道。蒸馏度封顶 0.85，Trust Card 标注补录来源；返回 `versionId` 可继续走草稿编辑→生成 skill 包→发布门禁 |
| `detectVariant` | `GET /api/growth/skills/:id/version-candidates` | F12 反馈闭环，冷启动 2 次/2 人触发 |
| `listSkills`/`getSkill` | `GET /api/skills` | 后端技能并入本地 DB，id 加 `be-` 前缀；排序按 quality_score（任务证据），无评分排序 |
| `getTrustCard`（新增） | `GET /api/growth/skills/:id/trust-card` | 七分区+判断级溯源，响应里没有任何综合分 |
| `probeOrchestration`（新增） | `POST /api/growth/orch-probe` | 没人走过的方向会拒绝生成——这一幕建议放进路演 |

## 三、后端能直接复用的（不用改）

- **三态路由 + 四筛 + 五类伪需求拦截**（`growth_intent.go`）——和现在前端的四态概念完全同源
- **任务工作台**：advance / 关键判断停顿 / 工具调用 / 放弃判定（`growth_workbench.go`）
- **供给飞轮**：轨迹→四槽→蒸馏度六维→六 slot skill 包（`growth_creator.go`）
- **发布门禁四问**（边界停机 100% 不可下调）+ 门禁失败反向指导（`growth_gate.go`）
- **Trust Card 判断级溯源**、反馈驱动版本升级（`growth_trust_loop.go`）
- **编排态**：orch-probe / interview / 采纳 / 周复核，只输出绝对人数（`growth_orchestration.go`）
- 认证 JWT、Skill 市场 CRUD、zip 上传下载、评价、论坛、通知、评测管道

## 四、后端缺的（前端概念在后端没有对应，需要补或留在前端层）

1. **阶段体系（大0–研一）**：后端无阶段概念。当前由前端 `guessStage()` 关键词路由；
   要后端化的话给 `skills` 表加 `stage` 列 + interpret 出参带 stage 即可。
2. **路口（junction）分支人数**：后端 `lifeDecisionBranches()` 有雏形，但数据是种子语料；
   前端 `DB.junctions` 的分布数据要导入后端。
3. **金币/心意机制**：后端无定价体系（PRD 里 F15 是 P2 未做）。
4. **GitHub 真实 Skill（rs1–rs15）**：可用 `backend/tools/import_skills` 批量导入后端市场。
5. **陪跑的"装载 Skill 注入 system prompt"**：工作台 prompt 目前不吃 skill 包内容，
   要在 `askNextStep` 里把已装载 skill 的 SKILL.md 拼进 system prompt（一处小改）。
