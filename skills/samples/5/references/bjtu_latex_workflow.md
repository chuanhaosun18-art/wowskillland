# BJTU LaTeX And Dual Output Workflow

This reference defines how to produce BJTU LaTeX/PDF output alongside Word/DOCX output.

## Source Of Truth

Use chapter Markdown as the primary source of truth while drafting:

- `03_chapters/chXX_draft.md` for chapter text;
- `04_figures/figures_manifest.md` for figures;
- `05_tables/tables_manifest.md` for tables;
- `08_refs/` and `reference/ref.bib` for references.

DOCX and PDF are generated artifacts. If a user edits DOCX manually after generation, reverse parse or reconcile those changes before regenerating LaTeX/PDF.

## Class Option

Choose conservatively:

- `EnMaster`: professional master's degree draft;
- `AcMaster`: academic master's degree draft;
- `Doctor`: doctoral draft.

If the user is a professional master's student and does not specify otherwise, use `EnMaster`.

## Reference Rules

For BJTU PDF, do not hand-write the final reference list.

Use:

```latex
\bibliography{reference/ref}
```

The class file already specifies:

```latex
\bibliographystyle{GBT7714-2005NLang}
```

Use `\cite{key}` for citations. The template loads `natbib` with superscript numeric citations.

For web references, use BibTeX entries such as:

```bibtex
@online{nea2025power,
  author = {{国家能源局}},
  title = {国家能源局发布2024年全国电力工业统计数据},
  year = {2025},
  month = {01},
  day = {21},
  refdate = {2026-06-21},
  url = {https://www.nea.gov.cn/...}
}
```

Note: the bundled `.bst` may output only the publication year plus access date for online references, for example `2025 [2026-06-21]`. That is template behavior.

## LaTeX Project Generation

Use the copied scripts:

```bash
python3 <skill_dir>/scripts/init_bjtu_project.py \
  --output <latex_project> \
  --class-option EnMaster \
  --author "<name>" \
  --student-number "<number>" \
  --advisor "<advisor>" \
  --engineering-master-field "<field>" \
  --degree-type "<degree>" \
  --major "<major>" \
  --research-area "<area>" \
  --title "<title>" \
  --english-title "<english_title>" \
  --date "<date>"
```

If migrating an existing LaTeX project:

```bash
python3 <skill_dir>/scripts/migrate_to_bjtu_template.py \
  --source <source_latex_project> \
  --output <output_bjtu_project> \
  --class-option EnMaster \
  ...
```

Compile:

```bash
python3 <skill_dir>/scripts/compile_pdf.py \
  --project <latex_project> \
  --copy-to <final.pdf>
```

Validate:

```bash
python3 <skill_dir>/scripts/validate_pdf.py \
  --project <latex_project> \
  --must-contain "参考文献"
```

## Markdown To LaTeX Conversion Expectations

When converting chapter Markdown manually or with helper scripts:

- `#` maps to `\chapter`;
- `##` maps to `\section`;
- `###` maps to `\subsection`;
- figures should be copied to `figures/` and referenced with `\includegraphics`;
- equations should become LaTeX math, not screenshot images unless unavoidable;
- tables should use `tabular`, `longtable`, or image fallback only when source tables cannot be reconstructed;
- citations should be `\cite{key}`.

## Formula Policy

If formulas come from Word and are damaged or plain text:

- inspect surrounding prose;
- compare with previous LaTeX/PDF versions if available;
- restore formulas using LaTeX math only when the intended formula is clear;
- otherwise mark `待确认公式`.

Do not silently invent formulas.

## Validation Checklist

Before handing off:

- `main.pdf` exists;
- `main.bbl` exists if references are used;
- no unresolved `Citation ... undefined`;
- extracted PDF text does not contain `??`;
- TOC reflects actual body headings;
- images are present and in expected order;
- formulas render as math;
- references are generated by `GBT7714-2005NLang.bst`, not hand-written lists;
- final PDF has been copied to the user-facing output path.

Non-blocking warnings after verification:

- macOS font reproducibility warnings;
- `fancyhdr` one-sided `E` option warnings;
- some overfull boxes from long URLs or long English titles, if the PDF is readable.
